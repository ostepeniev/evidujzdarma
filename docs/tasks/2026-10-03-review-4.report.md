## Коміт `92d54ab` — R7.1: robots.txt не блокує `/ucetni` (B N1)

1. **Коміти:** `92d54ab`.
2. **Було → стало** (`apps/web/src/app/robots.ts`):
   - **Було:** кожна закрита секція потрапляла в Disallow і як `/u`, і як `/u/`. Disallow — це префікс, тож правило `/u` закривало й `/ucetni`, `/ucetni/hromadna-kontrola`, `/ucetni/sablony`.
   - **Стало:** `/u$` (точний збіг) і `/u/` (усе всередині). Так само для решти `CLOSED_SECTIONS`.
   - Гейт `test/open-site.test.ts` тепер вимагає саме пару `${p}$` + `${p}/`.
   - **Міграцій немає.**
3. **Гейт, що був червоним** (`test/r7-1-robots.test.ts`): жоден Disallow не блокує шлях із `STATIC_PAGES` (з урахуванням `$`). Було `['/ucetni <- /u', …]`. Контроль: `/u`, `/u/x`, `/pokladna`, `/pokladna/nastaveni`, `/firma/sitemap/0.xml` заблоковані.

   `pnpm -r test` (web 364), `pnpm -r typecheck` — зелені.
4. **Самостійні рішення:** —.
5. **Що не вдалося / перевірити:** чи SeznamBot розуміє `$`.
   - Якщо ні — він бачить `/pokladna$` як буквальний шлях, і точна адреса `/pokladna` для нього формально не заборонена.
   - Підшляхи `/pokladna/` заборонені в будь-якому разі, а саму сторінку закриває пароль (401) і `noindex` у `(app)/layout`.

## Коміт `a00ed95` — R7.2: інфра-тест конфігу nginx (B N2)

1. **Коміти:** `a00ed95`.
2. **Було → стало:**
   - **Нове: `apps/web/test/helpers/nginx.ts`.** Мінімальний парсер конфігу nginx (директиви, блоки, лапки, коментарі) і вибір `location`, як у nginx:
     - `=` → найдовший префікс;
     - якщо це `^~` — кінець;
     - інакше перший regex (`~`, `~*`) у порядку файлу, а якщо жоден не збігся — найдовший префікс.
   - `effectiveAuth` бере `auth_basic` з location, а якщо його там немає — серверний.
   - **Нове: `apps/web/test/infra.test.ts`** читає `infra/nginx/evidujzdarma.conf` і перевіряє:
     - для кожного шляху з `CLOSED_SECTIONS` і `CLOSED_API` (`p`, `p/`, `p/x`, а також `/api/ucet/certifikat`, sitemap каталогу, `/u/<uuid>`) — фактичний `auth_basic`, не `off`;
     - `/api/pokladna/x` → `auth_basic off`;
     - жодна location не має власного `proxy_set_header`.
   - **Конфіг nginx не змінено** (контролер).
3. **Гейт, що був червоним:**
   - **План дня відкриття з `open-site.md` на `1aec031`** (серверний `auth_basic` прибрано, закриті секції — regex-ом, exact `/api/ucet/certifikat` без пароля) → тест знаходить порушення `/api/ucet/certifikat: bez auth_basic`. Тест перевіряє саме, що порушення є.
   - **Зелені:**
     - поточний конфіг (пароль на рівні `server`, `^~ /api/pokladna/` з `auth_basic off`);
     - блок із B-r4, розд. 3 (беру його прямо з `B-r4.md`).
   - **Контролі:**
     - location із власним `proxy_set_header` → порушення;
     - вибір location: exact перемагає regex, `^~` зупиняє regex, `/ucetni` іде в `location /` без пароля.

   `pnpm -r test` (web 367), `pnpm -r typecheck` — зелені.
4. **Самостійні рішення:**
   - Блок із B-r4 тест читає прямо з `B-r4.md`, а не з копії: копія могла б розійтися з рецензією.
   - Нормалізацію шляхів (`%xx`, `//`) тест не моделює — nginx робить її сам до вибору location.
5. **Що не вдалося:** —. Після заміни третього `server` контролером тест перевірить уже новий конфіг.

## Коміт `fcc2115` — R7.3: відписка не подовжує зберігання передреєстрації (B N3, Z1)

1. **Коміти:** `fcc2115`.
2. **Було → стало:**
   - **`app/api/odhlasit/route.ts` (POST):**
     - **було:** ставився `unsubscribedAt` і `marketingConsent=false`, решта запису лишалась. Retention виключає відписаних із правил «90 днів» і «launch + 12 міс.», тож увесь запис (IČO, назва, obor, UTM…) лежав 3 роки;
     - **стало:** після відписки обнуляються `ico`, `companyName`, `industry`, `establishmentsCount`, `needs`, `utm`, `referredBy`;
     - обов'язкові стовпці отримують випадкові значення, що нікуди не ведуть: `referralCode` — новий випадковий код, `confirmTokenHash` — хеш випадкового токена (посилання стану перестає працювати);
     - **без згоди** (`marketingConsentAt` порожній) обнуляються ще й `confirmedAt` і `consentEvidence` — лишаються адреса й `unsubscribedAt`;
     - **зі згодою** лишається доказ: `email`, `consentEvidence`, `marketingConsentAt`, `confirmedAt`, `unsubscribedAt`.
   - **Retention** не змінено: запис-блокування живе 3 роки (`RETENTION.consentProofYears`).
   - **Zásady** — дослівно з рецензії:
     - `PURPOSES[0].retention`: у кінець дописано «Odhlásíte-li se z našich e-mailů, … (3 roky).»;
     - `PURPOSES[1].retention`: замінено на «Do odvolání souhlasu. Doklad o souhlasu a jeho odvolání (e-mail, datum a verzi textu souhlasu) … po odvolání smažeme.».
   - **`lib/legal.ts`:** `TERMS_VERSION` і `PRIVACY_VERSION` = `2026-10-03-r7`, мітки «3. 10. 2026» (дата коміту, Z10). Дату публікації контролер виставить у день відкриття.
   - **Міграція `0026_prereg_unsubscribed_minimise`** (лише дані): те саме для вже відписаних рядків. Активні записи не змінюються.
3. **Гейти, що були червоними** (`test/integration/r7-3-unsubscribe-retention.test.ts`):
   - непідтверджений запис з IČO, obor, UTM, ref → POST `/api/odhlasit` → `runRetention(+120 d)` → у записі лише адреса й `unsubscribedAt`. Було: увесь запис;
   - зі згодою (DOI) → `ico`, `companyName`, `utm` = null, доказ згоди лишився. Було: усе лишалось;
   - тексти zásad — дослівно. Було: тексту не було;
   - міграція 0026: старі відписані мінімізовано (зі згодою доказ лишився, код змінено), активний запис без змін.

   `pnpm -r test` (web 371), `pnpm -r typecheck` — зелені.
4. **Самостійні рішення:**
   - **Запис не видаляю, а лишаю як блокування** (варіант із рецензії). Інакше та сама адреса знову отримувала б листи.
   - **`referralCode` міняю на новий випадковий.** Старий код вів на людину, яка відписалась. Кого вона раніше рекомендувала — лишається в їхніх записах (`referredBy`), але винагороду їй уже не приписати.

5. **Що не вдалося:** перший прогін гейту впав з іншої причини: у тесті був неіснуючий `industry`, і запис не створювався. Виправив тест і перевірив, що без коду гейт червоний саме через лишки даних.
