## Коміт `92d54ab` — R7.1: robots.txt не блокує `/ucetni` (B N1)

1. **Коміти:** `92d54ab`.
2. **Було → стало** (`apps/web/src/app/robots.ts`):
   - **Було:** кожна закрита секція потрапляла в Disallow і як `/u`, і як `/u/`. Disallow — це префікс, тож правило `/u` закривало й `/ucetni`, `/ucetni/hromadna-kontrola`, `/ucetni/sablony`.
   - **Стало:** `/u$` (точний збіг) і `/u/` (усе всередині). Так само для решти `CLOSED_SECTIONS`.
   - Гейт `test/open-site.test.ts` тепер вимагає саме пару `${p}$` + `${p}/`.
   - **Міграцій немає.**
3. **Гейт, що був червоним** (`test/r7-1-robots.test.ts`): жоден Disallow не блокує шлях із `STATIC_PAGES` (з урахуванням `$`). Було `['/ucetni <- /u', …]`. Контроль: `/u`, `/u/x`, `/pokladna`, `/pokladna/nastaveni`, `/firma/sitemap/0.xml` заблоковані.

   `pnpm -r test` (web 364), `pnpm -r typecheck` — зелені.
4. **Самостійні рішення:** —.
5. **Що не вдалося / перевірити:** чи SeznamBot розуміє `$`.
   - Якщо ні — він бачить `/pokladna$` як буквальний шлях, і точна адреса `/pokladna` для нього формально не заборонена.
   - Підшляхи `/pokladna/` заборонені в будь-якому разі, а саму сторінку закриває пароль (401) і `noindex` у `(app)/layout`.

## Коміт `a00ed95` — R7.2: інфра-тест конфігу nginx (B N2)

1. **Коміти:** `a00ed95`.
2. **Було → стало:**
   - **Нове: `apps/web/test/helpers/nginx.ts`.** Мінімальний парсер конфігу nginx (директиви, блоки, лапки, коментарі) і вибір `location`, як у nginx:
     - `=` → найдовший префікс;
     - якщо це `^~` — кінець;
     - інакше перший regex (`~`, `~*`) у порядку файлу, а якщо жоден не збігся — найдовший префікс.
   - `effectiveAuth` бере `auth_basic` з location, а якщо його там немає — серверний.
   - **Нове: `apps/web/test/infra.test.ts`** читає `infra/nginx/evidujzdarma.conf` і перевіряє:
     - для кожного шляху з `CLOSED_SECTIONS` і `CLOSED_API` (`p`, `p/`, `p/x`, а також `/api/ucet/certifikat`, sitemap каталогу, `/u/<uuid>`) — фактичний `auth_basic`, не `off`;
     - `/api/pokladna/x` → `auth_basic off`;
     - жодна location не має власного `proxy_set_header`.
   - **Конфіг nginx не змінено** (контролер).
3. **Гейт, що був червоним:**
   - **План дня відкриття з `open-site.md` на `1aec031`** (серверний `auth_basic` прибрано, закриті секції — regex-ом, exact `/api/ucet/certifikat` без пароля) → тест знаходить порушення `/api/ucet/certifikat: bez auth_basic`. Тест перевіряє саме, що порушення є.
   - **Зелені:**
     - поточний конфіг (пароль на рівні `server`, `^~ /api/pokladna/` з `auth_basic off`);
     - блок із B-r4, розд. 3 (беру його прямо з `B-r4.md`).
   - **Контролі:**
     - location із власним `proxy_set_header` → порушення;
     - вибір location: exact перемагає regex, `^~` зупиняє regex, `/ucetni` іде в `location /` без пароля.

   `pnpm -r test` (web 367), `pnpm -r typecheck` — зелені.
4. **Самостійні рішення:**
   - Блок із B-r4 тест читає прямо з `B-r4.md`, а не з копії: копія могла б розійтися з рецензією.
   - Нормалізацію шляхів (`%xx`, `//`) тест не моделює — nginx робить її сам до вибору location.
5. **Що не вдалося:** —. Після заміни третього `server` контролером тест перевірить уже новий конфіг.
